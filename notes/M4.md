# M4 — Reading and Verifying Output

## Bug hunt #1 — SQL injection
- Bug: The query is built with an f-string — `f"SELECT ... LIKE '%{q}%'"` — so user input lands directly in the SQL string. An attacker can inject `%' UNION SELECT username, password FROM users; --` and read arbitrary tables.
- Why Claude wrote it: String-interpolated SQL is everywhere in older tutorials and Stack Overflow answers; it produces correct output for normal inputs, so it looks plausible without thinking about adversarial inputs.
- Fix: Use a parameterized query so the driver escapes the value: `db.session.execute(text("SELECT id, title FROM notes WHERE title LIKE :q"), {"q": f"%{q}%"})` — or use the ORM: `Note.query.filter(Note.title.like(f"%{q}%")).all()`.
