- Add `starred: false` field to each note dict

- Step 4: update UI rendering

## Retro

I used chat for planning the starred notes feature, which helped clarify the data model and UI structure before any coding. Claude Code handled implementation, especially adding the starred field and filter logic. Copilot was useful only for small edits like renaming variables and adding docstrings, where agent-level overhead would be unnecessary.

The chat review caught a missing edge case: handling notes without a starred field safely in filtering logic. I fixed this by defaulting missing values to False.

If I redid this, I would tighten the initial chat design to explicitly define filter behavior before implementation to avoid minor ambiguity during coding.

Most of my time as conductor was spent during review and debugging rather than planning, which is correct because that's where correctness risk is highest.
